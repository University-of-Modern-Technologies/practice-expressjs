# 0010. Опис API виводиться з коду, відмови оголошуються руками

**Статус:** прийнято

## Контекст

Опис API (OpenAPI, Swagger UI на `/api/docs`) читають ті, хто пише клієнт, і ті,
хто вперше заходить у код. Опис, який пишуть окремо від коду, старіє з першої ж
правки: поле додали в схему валідації, а в описі його немає, маршрут
перейменували, а опис показує старий шлях. Розбіжність ніхто не помічає, бо опис
нічого не виконує.

Водночас не все можна вивести автоматично. Схему запиту й тіло успішної відповіді
код знає. А от чим операція може відмовити — застарілою версією, відсутнім
записом, станом, що забороняє дію, — знає лише сервіс під обробником, і ці
відмови існують тільки як помилки, кинуті десь глибше.

## Рішення

- **Маршрут і його опис — один виклик.** Роутер реєструє маршрути через
  `describeRoutes(router, tags)` (`backend/src/common/openapi/routes.ts`):
  шлях, короткий опис операції, схема успішної відповіді, потім звичайний
  ланцюжок обробників Express. Схема запиту не повторюється — вона береться з
  проміжного обробника `validate(...)` у тому ж ланцюжку. Схеми — ті самі Zod-схеми,
  що перевіряють запит (`zod-openapi`).
- **Документ збирається з роутерів, які справді змонтовані**
  (`backend/src/openapi.ts`, `backend/src/common/openapi/document.ts`), без
  сервера й без сховищ. `400` і `500` додаються до операцій за правилом.
- **Відмови оголошуються руками поруч із маршрутом:**
  `refusals: refusals(401, 403, 404, 409)`
  (`backend/src/common/openapi/refusals.ts`), а коди помилок перелічені в тексті
  опису операції. Тіло будь-якої відмови — спільний конверт помилки
  `ErrorResponse`.
- **Опис лежить у репозиторії** — `backend/openapi.json`. Після зміни API його
  перегенеровують з теки `backend` командою `npm run openapi:generate` і
  комітять разом зі зміною.
- **Тести тримають опис чесним** і входять у звичайний `npm test`, а отже в
  `check:api` і CI:
  - `backend/src/openapi.drift.test.ts` — закомічений файл збігається з тим, що
    будує код, і з тим, що віддає `/api/openapi.json`;
  - `backend/src/openapi.routes.test.ts` — кожен змонтований маршрут або
    описаний, або свідомо лишений поза описом, і в описі немає маршрутів, яких
    не існує;
  - `backend/src/openapi.refusals.test.ts` — механічні правила для відмов:
    операція з `version` оголошує `409`, захищена операція — `401`.

## Наслідки

- Операції, параметри й поля в описі не можуть розійтися з кодом: вони
  беруться звідти ж, а дрейф закоміченого файла ламає CI.
- Відмови можуть відставати. Нова гілка логіки, що кидає `404` чи `409`, сама в
  опис не потрапляє, і тести ловлять лише ті пропуски, що мають механічну
  ознаку. Решту перевіряє людина на review: змінилася логіка відмов — має
  змінитися і `refusals(...)` поруч із маршрутом.
- Зміна API видна в дифі pull request як зміна `openapi.json`, тож рев'ювер
  бачить наслідок для клієнта, не читаючи сервіс.
- `/api/docs` і `/api/openapi.json` вимкнені в production
  (`API_DOCS_ENABLED`, типово `false` при `APP_ENV=production`); на машині
  розробника й у тестах вони є.
